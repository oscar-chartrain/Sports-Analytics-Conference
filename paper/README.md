# Paper-facing materials

This folder holds everything meant to be read as part of the submission itself: the SSAC abstract draft and any later drafts, plus material used to write them.

- `application_and_impact.md`: the case for SSAC's application and interest/impact criteria, grounded in what the analysis actually found. Ends with a distilled version adapted into the abstract's Conclusion section.
- `statistics_explained.md`: a plain-English companion to every statistical term used in the abstract and docs (entropy, correlation, p-value, confidence intervals, Bonferroni correction, TOST equivalence bounds, split-half reliability, disattenuation), each with its scale, how to read a big vs. small value, and this project's own numbers as worked examples. No new analysis, just a reference for numbers that already exist elsewhere in `docs/`.
- `abstract.md`: the SSAC submission draft, structured into the required Introduction / Methods / Results / Conclusion sections, 466 words excluding figure captions / 486 including them by a markdown-level count (limit fewer than 500, title included; counted by whitespace-split words, not naively splitting on hyphens). The number that actually matters is the rendered `abstract.pdf`'s own full-text count, 490 words, since that counts everything a reviewer would see by selecting all text on the page: title, the four section headers ("Introduction" etc., which a markdown-level count skips since they're heading syntax, not body prose), body, and captions. An earlier PDF draft that also folded each figure's alt-text description into its caption came in at 501, over the limit, caught by the author counting the actual PDF rather than trusting the markdown-level figure; the redundant alt-text was removed from the captions and six more words trimmed from the body to reach the current 490. Two figures and no table (SSAC's rule allows up to two tables/figures combined). The title, Results, and Conclusion all lead with the reliability-warning finding ahead of the entropy null, per the reasoning in `application_and_impact.md`, while still fully reporting the null; the title itself no longer names the null explicitly (dropped "...and a Null Result"), consistent with that same lead-with-the-stronger-claim decision applied everywhere else in the document. It also states in one clause why return-side reliability is worse than serve-side (return clutch depends on the opponent's serve quality, a source of variance self-driven serve clutch doesn't share), and notes the shrinkage follow-up (`docs/atp/04_regression_results/shrinkage_reliability.md`), a real fix that narrows the reliability gap without closing it, which heads off the obvious reviewer question of why not just correct for it statistically. The Conclusion's application sentence names one concrete, falsifiable action (ask for split-half reliability before citing a return-clutch rating) instead of a general norm aimed at metric publishers.

  The ordering went through a few rounds of revision. An early draft put the entropy null first in both Results and Conclusion; even with "more consequential result" language pointing at the reliability finding, the null still read as the headline, since prose claims about importance don't override what a skimming reader hits first. After reordering, two more gaps turned up: the Results prose said return clutch reliability was below the 0.70 threshold but didn't say the same about serve (0.57-0.58), which implicitly oversold serve as the "clean" side; and the null result being Bonferroni-corrected across all comparisons (a real rigor claim) had only ever made it into `docs/`, never the abstract. Both are fixed now. One more gap: once serve is honestly labeled sub-threshold too, there's no reliability-clean side left to argue the null isn't itself an attenuation artifact. The Results section now answers that directly instead of leaving it implicit: correcting the equivalence bound for both variables' own reliability leaves ATP's claim intact but pushes the WTA return bound past 1 (`docs/atp/04_regression_results/disattenuated_equivalence_bounds.md`).

  Word count is under the 500-word cap with real margin: 490 words on the actual rendered `abstract.pdf`, everything on the page included. Still worth a check against SSAC's own portal word counter as the last sanity check before submitting, since counting conventions can differ.

## Figures

The results table originally in `abstract.md` was dropped in favor of two figures; their numbers were already stated in the Results prose, and figures can show something prose can't: how the estimates actually distribute, not just their point values. Figure numbering follows the abstract's current order (reliability finding first, entropy null second), not build order.

- `results/figures/split_half_reliability_figure.png`, Figure 1, the reliability finding: half-A vs. half-B scatter, three panels (entropy, serve clutch, return clutch), all showing the Spearman-Brown-corrected r reported in the abstract's prose, not the raw split-half r. An earlier two-panel version (entropy vs. return clutch only, raw r in the legend) had two problems: showing raw r in the figure while the text reported the corrected value read as inconsistent, and leaving out serve clutch understated the reliability story despite it being discussed in text. Both are fixed by construction now, not by an explanatory footnote. Built from real per-player data: `src/figures/export_split_half_data.py` reuses `split_half_reliability.py`'s functions unchanged to export the per-player half-A/half-B values that script computes but never persists, and `src/figures/make_reliability_figure.py` plots them. The exported CSVs (`results/figures/split_half_raw_{atp,wta}.csv`) were checked against `split_half_reliability.md`'s documented Pearson r values before the figure was trusted: exact match on all six (ATP/WTA × entropy/serve/return).
- `results/figures/disattenuation_figure.png`, Figure 2, replacing an earlier forest plot of the primary null result. The forest plot showed every entropy-clutch correlation's CI crossing zero: correct, but visualizing the least novel part of the paper, and only for the primary p65 variant, not the "all five leverage variants" the Results prose claims robustness across. This figure instead visualizes the disattenuation result (`docs/atp/04_regression_results/disattenuated_equivalence_bounds.md`): for each tour/role, a dumbbell from the observed-scale TOST equivalence bound to the reliability-corrected (true-score) bound, with the region past |r|=1 shaded to make "vacuous" a visual fact rather than a sentence to parse. WTA return's corrected bound (1.81) lands inside that shaded region; ATP's two bounds and WTA serve's stay left of it. Built by `src/figures/make_disattenuation_figure.py`, which imports `src/robustness/disattenuated_equivalence_bounds.py` directly and reuses its `tightest_tost_bound()` search and already-documented quartile-reliability dictionaries unchanged, no new analysis, and it asserts its recomputed ATP bounds match `DOCUMENTED_ATP_BOUNDS` before saving anything. Uses quartile (not shrinkage-corrected) reliabilities throughout, matching `split_half_reliability_figure.png`'s basis, so the two figures stay on the same footing. The retired forest plot (`results/figures/null_forest_figure.png`, `src/figures/make_null_forest_figure.py`) is still valid and still in the repo: it just no longer earns one of the abstract's two figure slots.
